Câu 1 (10 điểm): Phân biệt position: relative và absolute

1. Khái niệm

position: relative dùng để định vị phần tử tương đối so với vị trí ban đầu của chính nó. Phần tử vẫn giữ chỗ trong bố cục trang web.

position: absolute định vị phần tử dựa trên phần tử tổ tiên gần nhất có thuộc tính position khác static. Nếu không có phần tử phù hợp, phần tử sẽ được định vị theo khung chứa ban đầu của trang. Phần tử không còn chiếm chỗ trong bố cục thông thường.

2. Bảng so sánh

Tiêu chí Relative Absolute
Vị trí tham chiếu Vị trí ban đầu của chính nó Phần tử tổ tiên có định vị phù hợp
Không gian bố cục Vẫn được giữ lại Không được giữ lại
Ứng dụng Dịch chuyển phần tử, tạo khung tham chiếu Đặt nhãn, biểu tượng chồng lên nội dung

3. Ví dụ minh họa

<style>
.container {
    position: relative;
    width: 300px;
    height: 150px;
    background: lightblue;
}

.relative-box {
    position: relative;
    top: 10px;
    left: 20px;
    background: lightgreen;
}

.absolute-box {
    position: absolute;
    right: 10px;
    bottom: 10px;
    background: orange;
}
</style>

<div class="container">
    <div class="relative-box">Relative</div>
    <div class="absolute-box">Absolute</div>
</div>

4. Responsive và triển khai website

Trong thiết kế responsive, relative thường được dùng để tạo khung tham chiếu cho phần tử con. Absolute phù hợp với các thành phần cần đặt chồng lên hình ảnh hoặc nội dung.

Khi deploy lên hosting, CSS vẫn hoạt động bình thường. Tuy nhiên, việc dùng tọa độ cố định có thể làm giao diện lệch trên điện thoại. Nên kết hợp Flexbox, Grid, đơn vị linh hoạt và media queries để website hiển thị tốt trên nhiều thiết bị.

Kết luận: Relative giữ chỗ trong bố cục và dịch chuyển từ vị trí ban đầu; absolute tách khỏi bố cục thông thường và định vị theo khung chứa phù hợp.

Câu 2 (10 điểm): Quy trình đăng ký Domain và cấu hình Hosting

1. Khái niệm

  • Domain: Tên miền, là địa chỉ của website, ví dụ example.com.
  • Hosting: Dịch vụ lưu trữ các tệp và dữ liệu để website có thể hoạt động trên Internet.
  • DNS: Hệ thống phân giải tên miền, giúp trình duyệt tìm đến địa chỉ IP hoặc dịch vụ tương ứng với tên miền.

2. Quy trình triển khai website

  1. Tạo website bằng HTML, CSS và JavaScript.
  2. Kiểm tra website trên trình duyệt.
  3. Đăng ký tên miền thông qua nhà đăng ký tên miền.
  4. Chọn hosting phù hợp với website.
  5. Đưa mã nguồn lên hosting hoặc kết nối với GitHub.
  6. Cấu hình DNS theo hướng dẫn của nhà cung cấp.
  7. Kiểm tra website và bật HTTPS.

3. Công cụ hỗ trợ triển khai

GitHub Pages: Cho phép xuất bản website tĩnh trực tiếp từ kho GitHub, phù hợp với dự án HTML, CSS và JavaScript.

Netlify: Hỗ trợ deploy website từ kho mã nguồn, tự động cập nhật khi có thay đổi và hỗ trợ cấu hình tên miền, HTTPS tùy dịch vụ.

4. Vai trò của DNS và rủi ro bảo mật

Khi người dùng nhập tên miền, DNS giúp xác định dịch vụ hoặc máy chủ tương ứng để trình duyệt truy cập website.

Các rủi ro khi cấu hình không đúng gồm:

  • Tên miền không truy cập được do bản ghi DNS sai.
  • Tài khoản quản lý tên miền bị chiếm quyền.
  • Thông tin nhạy cảm bị lộ khi đưa vào mã JavaScript công khai.
  • Kết nối không được bảo vệ nếu thiếu HTTPS.

Để hạn chế rủi ro, cần dùng mật khẩu mạnh, bật xác thực đa yếu tố, kiểm tra bản ghi DNS, bật HTTPS và không lưu khóa bí mật trong mã nguồn phía trình duyệt.

Kết luận: Domain là địa chỉ, hosting là nơi cung cấp dịch vụ lưu trữ và DNS giúp kết nối tên miền với website. GitHub Pages và Netlify là các lựa chọn thuận tiện để triển khai website tĩnh mà không cần tự quản lý máy chủ riêng.

Câu 3 (10 điểm): So sánh var, let và const trong JavaScript

1. Khái niệm

var, let và const là các từ khóa dùng để khai báo biến trong JavaScript. Chúng khác nhau về phạm vi, khả năng gán lại và cách hoạt động khi hoisting.

2. Bảng so sánh

Tiêu chí var let const
Phạm vi Hàm hoặc toàn cục Khối lệnh Khối lệnh
Khai báo lại Có thể Không thể trong cùng phạm vi Không thể trong cùng phạm vi
Gán lại giá trị Có thể Có thể Không thể
Hoisting Khởi tạo bằng undefined Không thể truy cập trước khai báo Không thể truy cập trước khai báo

3. Ví dụ lỗi thường gặp

console.log(age);

let age = 20;

Đoạn code trên gây lỗi ReferenceError vì biến age được truy cập trước khi dòng khai báo let được thực thi. Khoảng thời gian này được gọi là Temporal Dead Zone.

Ví dụ về sự khác biệt phạm vi:

if (true) {
    var name = "Hieu";
}
console.log(name); // Hieu

if (true) {
    let score = 8;
}
console.log(score); // ReferenceError

4. Debug bằng Chrome DevTools

  1. Mở website bằng Chrome.
  2. Nhấn F12 để mở DevTools.
  3. Chọn Console để xem thông báo lỗi.
  4. Chọn Sources để mở tệp JavaScript và đặt breakpoint.
  5. Tải lại trang, kiểm tra giá trị biến trong Scope.
  6. Sửa code và chạy lại để xác nhận lỗi đã được khắc phục.
Kết luận: Nên ưu tiên const khi không cần gán lại biến và dùng let khi giá trị cần thay đổi. Hạn chế var để giảm các lỗi liên quan đến phạm vi biến.

Câu 4 (10 điểm): Event Delegation trong JavaScript

1. Khái niệm

Event Delegation (ủy quyền sự kiện) là kỹ thuật gắn một trình xử lý sự kiện vào phần tử cha để xử lý sự kiện phát sinh từ các phần tử con. Kỹ thuật này dựa trên cơ chế event bubbling, tức sự kiện có thể lan truyền từ phần tử con lên phần tử cha.

2. Ví dụ danh sách động

<ul id="taskList">
    <li>Học HTML</li>
    <li>Học CSS</li>
</ul>

<script>
const taskList = document.getElementById("taskList");

taskList.addEventListener("click", function(event) {
    const item = event.target.closest("li");

    if (!item || !taskList.contains(item)) {
        return;
    }

    alert("Bạn đã chọn: " + item.textContent);
});

// Thêm một mục mới
const newItem = document.createElement("li");
newItem.textContent = "Học JavaScript";
taskList.appendChild(newItem);
</script>

3. Giải thích hoạt động

  • addEventListener() gắn sự kiện click vào phần tử cha.
  • event.target xác định phần tử được nhấp.
  • closest("li") tìm mục li gần nhất.
  • contains() kiểm tra mục có thuộc danh sách hay không.

4. Lợi ích khi kết hợp HTML và CSS

HTML tạo cấu trúc danh sách, CSS định dạng giao diện và JavaScript xử lý tương tác. Event Delegation giúp giảm việc gắn nhiều trình xử lý sự kiện, hỗ trợ các phần tử được thêm động và làm code dễ quản lý, bảo trì hơn.

Tuy nhiên, kỹ thuật này không phải lúc nào cũng nhanh hơn trong mọi tình huống. Cần kiểm tra đúng phần tử đích và lưu ý rằng không phải tất cả sự kiện đều nổi bọt theo cách thông thường.

Kết luận: Event Delegation là kỹ thuật hữu ích để xử lý sự kiện cho danh sách động, giảm mã lặp và hỗ trợ mở rộng website hiệu quả.
